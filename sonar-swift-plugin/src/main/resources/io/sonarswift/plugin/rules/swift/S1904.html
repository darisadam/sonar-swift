Why is this an issue?

A Task retains everything its closure captures until the task completes. For a long-running or never-finishing task (e.g. AsyncSequence consumption), strongly capturing self turns the enclosing view controller or coordinator into something that can't deallocate until the task ends — usually after the screen has disappeared, sometimes never.

Noncompliant code example

class ProfileViewController: UIViewController {
    func observeUpdates() {
        Task {                                            // Noncompliant — strong self
            for await event in self.events {
                self.label.text = event.title
            }
        }
    }
}

Compliant solution

class ProfileViewController: UIViewController {
    func observeUpdates() {
        Task { [weak self] in
            guard let self else { return }
            for await event in self.events {
                self.label.text = event.title
            }
        }
    }
}

Exceptions

If the task is bounded (e.g. a single await call that finishes promptly) and you actively want the surrounding object to live until the task finishes, capturing strongly is intentional. Annotate the call site with a comment or use [unowned self] if you can guarantee the lifetime.
