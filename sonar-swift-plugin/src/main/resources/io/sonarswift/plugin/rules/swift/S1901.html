Ask yourself whether

  • The type's stored state is truly immutable (every property is let and references only Sendable types).
  • If it is mutable, all access is gated behind a lock, serial dispatch queue, or other synchronization primitive that is documented adjacent to the declaration.
  • The class is final (subclasses can break the safety contract).

If any of these are uncertain, the type is racy and the @unchecked claim is wrong.

Recommended secure coding practices

// Prefer this: the compiler verifies it
final class IDGenerator: Sendable {
    let seed: UInt64
    init(seed: UInt64) { self.seed = seed }
}

// Only if you really need mutable shared state without an actor:
final class Cache: @unchecked Sendable {
    // Synchronized via an internal lock — documented and verified
    private let lock = NSLock()
    private var storage: [String: Data] = [:]

    func get(_ key: String) -> Data? {
        lock.withLock { storage[key] }
    }
}
