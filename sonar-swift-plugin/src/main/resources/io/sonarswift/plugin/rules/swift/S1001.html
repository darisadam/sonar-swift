Why is this an issue?

Force-unwrapping an optional (the trailing !) crashes the app at runtime if the value is nil. It hides a question every reader has to answer themselves: is this safe? Swift offers safer constructs (if let, guard let, ??) that prove the answer in code.

Noncompliant code example

let user = currentUser!                            // Noncompliant
print(user.displayName!.uppercased())              // Noncompliant

Compliant solution

guard let user = currentUser else { return }
let name = (user.displayName ?? "Unknown").uppercased()
print(name)

Exceptions

Tests sometimes use force-unwrap when a value must exist for the test to be meaningful (e.g. XCTUnwrap is preferred but legacy tests may use !). The rule is not active on files under **/Tests/** by default.
