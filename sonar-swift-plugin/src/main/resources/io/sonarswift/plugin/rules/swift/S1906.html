Why is this an issue?

An async call without await is a static error in Swift — but only when the compiler has full type information. With binary frameworks or generic constraints that obscure async-ness, the diagnostic can land at the wrong call site. This rule fires the same finding from a static-analysis perspective so editors and CI report it consistently.

Noncompliant code example

func process(_ pipe: Pipeline) async throws {
    let result = pipe.run()         // Noncompliant — pipe.run() is async, missing await
}

Compliant solution

func process(_ pipe: Pipeline) async throws {
    let result = await pipe.run()
}
