Why is this an issue?

A detached task inherits no isolation, no priority, and no actor context from its caller. It's useful for genuinely fire-and-forget background work, but using it as the default form of Task defeats Swift Concurrency's careful isolation propagation.

Noncompliant code example

func loadAndShow() {
    Task.detached {                              // Noncompliant — no isolation
        let data = try await network.fetch()
        await self.show(data)                     // probably a MainActor hop too
    }
}

Compliant solution

@MainActor
func loadAndShow() {
    Task {                                       // inherits MainActor
        let data = try await network.fetch()
        show(data)
    }
}

Exceptions

Long-running background work that genuinely needs to escape its caller's actor isolation (e.g. a daemon-style observer) is a legitimate use of Task.detached. Document the reason at the call site.
