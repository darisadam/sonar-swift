Why is this an issue?

When a value crosses an actor boundary — passed into Task { … }, sent across an async call to a different isolation domain, or returned from an actor method — Swift requires it to be Sendable. A reference type (class) is not automatically Sendable: two threads holding the same instance can race on its mutable state.

Noncompliant code example

final class Counter {                              // Noncompliant
    var value = 0
}

actor Service {
    func handoff(counter: Counter) { /* … */ }
}

Compliant solution

final class Counter: Sendable {                    // immutable storage
    let value: Int
    init(value: Int) { self.value = value }
}

// or — wrap in an actor for mutable state
actor Counter {
    private(set) var value = 0
    func bump() { value += 1 }
}

Exceptions

Types you explicitly mark @unchecked Sendable bypass this rule because the developer has made a manual safety claim. That claim is independently audited by rule S1901.
