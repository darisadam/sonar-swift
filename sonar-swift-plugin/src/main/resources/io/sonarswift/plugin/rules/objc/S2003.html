Why is this an issue?

A magic number — a numeric literal embedded in code with no name — leaves the reader guessing what it means. Naming the value documents intent and lets you reuse it.

Noncompliant code example

if (retries > 3) { ... }       // Noncompliant — what's 3?

Compliant solution

static const NSInteger MaxRetries = 3;
if (retries > MaxRetries) { ... }

Exceptions

{@code 0}, {@code 1}, {@code -1}, and numeric literals in unit tests are exempt.
